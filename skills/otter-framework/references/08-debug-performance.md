## 1. 先判断问题类型

先把问题分成四类：

- 不出图：窗口有了，但内容没出来。
- 不响应：图层有了，但点击/键盘没效果。
- 卡顿：能用，但掉帧、发热、GPU 占用高。
- 崩溃/异常：多半是生命周期、线程或后端 ABI 问题。

先看最小例子，再看当前项目。不要一上来就改大工程。

## 2. 白屏 / 不出图

按这个顺序排：

1. `win.get["__otter_canvas__"]` 是否为空。
2. `on_render` 是否真的绑定到了根层。
3. 回调有没有返回 `true` 持续触发。
4. 颜色是否透明到看不见。
5. 图层尺寸是不是 0。
6. 你是不是在子层里用了窗口坐标。

典型错误：

- 在 `on_render` 里临时创建图层。
- 以为 `LayoutPos` 子层还要再加父偏移。
- `Layer*` 指向的图层已经被销毁。

## 3. 输入无效 / 不响应

先看输入链路：

- 鼠标命中区域是否设置了 `hit_area` / `auto_hit_area(true)`。
- 键盘焦点是否切到了输入对象。
- `set_keyboard_target` 是否已调用。
- 浏览器类控件是否真的被 `focus(true)`。
- `transparent_hit_test` 是否把点击吞掉了。

如果是网络回调改 UI，必须先过主线程：

- worker 线程只收数据。
- 主线程每帧 `poll_events()`。

## 4. 卡顿 / 高占用

先做这几件事：

- 打开 `vsync(true)`。
- 确认没有把 `target_fps(0)` 当默认方案。
- Windows 端优先用 `render_mode(RenderMode::GPU)`。
- 把 `on_render` 里的分配、查找、构造都搬出去。
- 缓冲对象用复用，不要每帧 new。

性能判断顺序：

1. 先看是不是渲染频率太高。
2. 再看是不是每帧创建对象。
3. 再看是不是布局和命中测试太重。
4. 最后看是不是浏览器/视频/纹理路径。

## 5. 后端切换

切后端分两层：

- `render_backend(...)`：切窗口后端，通常会重建渲染器。
- `render_mode(...)`：切渲染算力模式，改变 GPU/CPU 路径。

选择建议：

- Windows 普通原生 UI：Direct2D。
- 跨平台 UI：OpenGL + GLFW。
- 需要浏览器透明混合：CEF OSR。
- 需要原生子窗口网页：WebView2。

切换前要确认：

- 后端支持的平台。
- 运行时库是否齐全。
- 编译器 ABI 是否匹配。

## 6. 强制 GPU

框架层强制 GPU 的入口是：

```cpp
win.render_mode(Otter::RenderMode::GPU);
```

这能把框架自己的渲染目标推到硬件路径上，但不代表所有子系统都自动拥有 GPU 解码或零拷贝。

注意：

- GPU 强制是“优先硬件渲染”，不是“所有东西都必定走硬件”。
- 如果浏览器层空白，先试 `use_shared_texture(false)`。
- 如果浏览器还要吃视频，记得看 codec 是否真的在 runtime 里。

## 7. 浏览器嵌入疑难

CEF / WebView2 常见问题：

- CEF 子进程入口必须先 `execute_subprocess()`。
- CEF 目标要用 MSVC。
- 运行时 DLL 必须和版本配套。
- 透明页面先检查 `transparent_hit_test`。
- 输入框不能打字，通常是键盘焦点没转发。
- 视频不播，先看 codec，再看命令行开关。

建议的调试顺序：

1. 先跑最小浏览器示例。
2. 先关 shared texture。
3. 再确认字体、透明度、焦点、命中测试。
4. 最后再优化帧率和纹理路径。
